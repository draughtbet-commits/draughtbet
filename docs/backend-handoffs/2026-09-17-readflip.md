# Backend handoff: Wallet read-flip onto the V2 ledger (PR 3)

Date: 2026-09-17
Branch: `refactor/backend-v2` (local only, not pushed)
Audience: frontend / Flutter wallet screen

## Summary

Every user-facing balance and transaction read now comes from the double-entry
V2 ledger (`LedgerAccount` / `LedgerEntry` / `LedgerTransaction`) instead of the
legacy `Wallet.balanceMinorUnits` column and `WalletTransaction` table, which
have been **removed**.

**The HTTP response shapes did not change.** The Flutter app needs no code
change. `wallet_screen.dart` and `WalletTransaction.fromJson` keep working
against the same payload fields.

## What is now ledger-backed

- `GET /wallet/balance` → `{ "balance": { "currency": "NGN",
  "balanceMinorUnits": "<available>" } }`, where `<available>` is the user's
  ledger `PLAYER_AVAILABLE` net. Key names and types unchanged.
- `GET /wallet/transactions` → the same `{ transactions, total, page,
  totalPages }` envelope; each row keeps the exact fields the app parses:
  `id`, `type`, `amountMinorUnits` (string), `status`, `createdAt`,
  `relatedMatchId`.
- `GET /auth/me` → `walletBalanceMinorUnits` is the same ledger net (string).

## Type mapping (ledger → app feed)

| Ledger transaction   | `type`       | `status`    | sign |
|----------------------|--------------|-------------|------|
| `DEPOSIT_CREDIT`     | `DEPOSIT`    | `COMPLETED` | `+`  |
| `STAKE_LOCK`         | `STAKE`      | `COMPLETED` | `-`  |
| `STAKE_RELEASE`      | `REFUND`     | `COMPLETED` | `+`  |
| `WITHDRAWAL_RESERVE` | `WITHDRAWAL` | `PENDING`   | `-`  |
| `WITHDRAWAL_RELEASE` | `REFUND`     | `COMPLETED` | `+`  |
| `SETTLEMENT_PAYOUT`  | `PAYOUT`     | `COMPLETED` | `+`  |
| `SETTLEMENT_PAYOUT` (draw, no winner) | `REFUND` | `COMPLETED` | `+` |

`ADJUSTMENT` (opening backfills) and `WITHDRAWAL_COMPLETE` (payout drain) are
internal legs and are **excluded** from the feed and from `total`, exactly as
the legacy mirror excluded them.

This preserves `wallet_screen.dart:145`
(`isPositive = type == 'DEPOSIT' || type == 'PAYOUT'`).

## What the app must not rely on anymore

- No `WalletTransaction` row exists; transaction `id`s are now ledger-entry ids
  (still opaque strings — treat as identifiers only).
- The balance column no longer exists server-side. Any direct DB read of
  `Wallet.balanceMinorUnits` will fail; clients must use the HTTP endpoints.
- Deposit/withdrawal semantics are unchanged from the PR 6 / PR 7 handoffs.
